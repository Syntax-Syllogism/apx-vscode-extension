# Extending the Extension

This guide covers common extension points and how to add new functionality.

## Adding Support for a New Command

If the apx plugin added a new command and you want to expose it in the extension:

### 1. Update the Oclif Manifest

First, check that the apx plugin version in your `package.json` has the new command. The oclif manifest is usually generated by the apx plugin at build time.

If you have the apx plugin source locally, regenerate it:

```bash
cd ../apx-cli-plugin
npm run oclif-manifest
cp dist/manifest.json ../apx-code-ext/vendor/apx.oclif.manifest.json
```

### 2. Add to Allowlist

Edit `scripts/gen-commands.ts` and add the command ID to the `allowList` set:

```typescript
const allowList = new Set([
  // ... existing commands
  'apx my new command',
]);
```

### 3. Add UI Metadata

In the same file, add mappings for title, group, and subgroup:

```typescript
const titleById = new Map([
  // ... existing
  ['apx my new command', 'SF Apx: My New Command'],
]);

const groupById = new Map([
  // ... existing
  ['apx my new command', 'AEP Generation'],  // the only group this extension uses today
]);

const subgroupById = new Map([
  // ... existing
  ['apx my new command', 'Pattern Layers'],  // or 'Selector Injection (AT4DX)', 'Domain Processes (AT4DX)'
]);
```

### 4. Regenerate Registry

```bash
npm run gen:commands
```

This creates the command definition in `src/registry/commands.generated.ts`.

### 5. Test

In the extension:

```bash
npm install
npm test
npm run compile
```

Then press F5 to launch the Extension Development Host and verify the new command appears in the Command Palette and sidebar.

## Adding Support for a New Flag Kind

Flag kinds determine how a flag's value is collected from the user. Here's how to add a new kind:

### 1. Define the Kind

Edit `src/registry/types.ts`:

```typescript
export type FlagKind = 'org' | 'file' | 'outputDir' | 'string' | 'boolean' | 'apiVersion' | 'enum' | 'newKind';
```

### 2. Add Inference Rule

In `scripts/gen-commands.ts`, add a case to `flagKind()`:

```typescript
function flagKind(name: string, flag: ManifestFlag): string {
  // ... existing cases
  if (name === 'my-special-flag') {
    return 'newKind';
  }
  // ...
}
```

### 3. Create the Input Method

Edit `src/input/gatherInputs.ts`. Add a method to the `InputApi` interface:

```typescript
export interface InputApi {
  // ... existing methods
  showNewKindPicker(label: string, options?: unknown[]): Promise<string | undefined>;
}
```

Then add handling in `gatherFlag()`:

```typescript
function gatherFlag(/* ... */) {
  // ...
  case 'newKind': {
    const value = await inputApi.showNewKindPicker(flag.summary);
    // ... validation and caching
    break;
  }
}
```

### 4. Wire the Implementation

In `src/input/gatherInputs.ts`, update `createVsCodeInputApi()`:

```typescript
function createVsCodeInputApi(): InputApi {
  return {
    // ... existing
    showNewKindPicker: async (label) => {
      return vscode.window.showInputBox({
        prompt: label,
        // ... your configuration
      });
    },
  };
}
```

### 5. Add Tests

In `src/test/extension.test.ts`, add the kind to the known set and write tests:

```typescript
const knownKinds = new Set(['org', 'file', 'outputDir', 'string', 'boolean', 'apiVersion', 'enum', 'newKind']);

describe('gatherFlag with newKind', () => {
  it('should call showNewKindPicker', async () => {
    const inputApi = createMockInputApi();
    // ... test your logic
  });
});
```

See [input-system.md](input-system.md#adding-a-new-flag-kind) for more details.

## Customizing Flag Metadata

To adjust how a flag is presented to users (placeholder, summary, ordering, exclusivity):

### Placeholders

In `scripts/gen-commands.ts`, add to `placeholderByCommandFlag` (currently empty — no apx flag needs one):

```typescript
const placeholderByCommandFlag = new Map([
  ['*:sobject', 'Account'],                       // Any command
  ['apx generate my-command:fieldName', 'MyField__c'], // Specific command
]);
```

### Summaries

Add to `summaryByCommandFlag`. Currently the only entries disambiguate the `--class-name`
flag's stale manifest summary between `apx generate action` and `apx generate criteria`:

```typescript
const summaryByCommandFlag = new Map([
  ['apx generate action:class-name', 'Action class name to generate.'],
  ['apx generate criteria:class-name', 'Criteria class name to generate.'],
]);
```

### Ordering

Edit `flagOrder()` to prioritize certain flags:

```typescript
function flagOrder(commandId: string, flagName: string): number {
  if (commandId === 'apx my command') {
    if (flagName === 'importantFlag') return -2;  // First
    if (flagName === 'secondFlag') return -1;     // Second
  }
  return 0;  // Default (rest in manifest order)
}
```

### Exclusive Groups

Create mutually exclusive flag groups in `exclusiveGroupFor()`:

```typescript
function exclusiveGroupFor(command: ManifestCommand, flagName: string): string | undefined {
  if (flagName === 'option1' || flagName === 'option2') {
    return 'myChoice';
  }
  return undefined;
}
```

Then in `gatherInputs()`, these flags are displayed as a single-select Quick Pick.
Give the group a human-readable prompt and per-option labels in
`exclusiveGroupPresentation()` (`src/input/gatherInputs.ts`); without an entry it
falls back to a generic `Choose <group>` prompt and `--flag` labels.

### Deferred (dependent) Flags

To defer a flag until a specific exclusive-group option is chosen, give it
`dependsOnFlag` via `dependsOnFlagFor()`:

```typescript
function dependsOnFlagFor(command: ManifestCommand, flagName: string): string | undefined {
  if (flagName === 'my-follow-up-flag' && /* command offers the relevant exclusive-group choice */) {
    return 'my-trigger-flag';  // only prompt after --my-trigger-flag is selected
  }
  return undefined;
}
```

A dependent flag is skipped in the normal prompt sequence and gathered as a
follow-up immediately after its target flag is selected inside the exclusive
group. No apx flag uses this today — `dependsOnFlagFor()` always returns
`undefined` — but the mechanism is shared with the sibling `warden-code-ext`
extension, which defers `--external-id` until `--users-def` is chosen. If the
dependent is `required` and left blank, the command aborts; otherwise a blank
simply omits it.

### Hiding Flags

To exclude a flag from the UI entirely, add to `guiHiddenFlagsByCommand` (currently empty — no apx command needs a hidden flag beyond the global `--json`/`--no-prompt`/`--api-version`/`--flags-dir` hides):

```typescript
const guiHiddenFlagsByCommand = new Map<string, Set<string>>([
  ['apx my command', new Set(['--flag-to-hide'])],
]);
```

After any of these changes, regenerate the registry:

```bash
npm run gen:commands
```

## Modifying the Sidebar Tree View

The tree view organization is defined in `src/tree/apxCommandsProvider.ts`. It groups commands into:

- **Groups** — Top-level (only `AEP Generation` today)
- **Subgroups** — Nested under the group (Pattern Layers, Selector Injection (AT4DX), Domain Processes (AT4DX))
- **Commands** — Leaf nodes

`orderedGroups()`/`orderedSubgroups()` derive bucket order from `commands.generated.ts`'s
own order (itself driven by the `allowList` order in `scripts/gen-commands.ts`) via a
`Map`, which preserves first-insertion order — there is no separately maintained ordering
array to edit. Commands are automatically grouped by their `group`/`subgroup` fields from
`CommandDef`. Change the group in `scripts/gen-commands.ts` → `groupById`/`subgroupById` maps.

## Adding Internal Flags

To automatically add flags to every command execution (like `--no-prompt`), edit `internalFlags()` in `src/runner/commandRunner.ts`:

```typescript
function internalFlags(command: CommandDef): string[] {
  const flags = [];
  if (command.supportsNoPrompt) {
    flags.push('--no-prompt');
  }
  // Add your new internal flag:
  if (command.id === 'apx.my.command') {
    flags.push('--my-flag=value');
  }
  return flags;
}
```

## Modifying Output Display

Command output is streamed to the Apx Output Channel. To customize how output is displayed:

### ANSI Color Stripping

Streamed stdout/stderr chunks are stripped of ANSI escape codes before being buffered for JSON-envelope detection and appended to the Output Channel (see `stripAnsi()` in `src/runner/ansi.ts`).

To change this behavior, edit the calls to `stripAnsi()` in `commandRunner.ts`.

### Output Formatting

To customize what's shown in the Output Channel before/after command execution, edit the logging in `runAndReport()` and `spawnWithProgress()`.

## Testing Your Changes

### Unit Tests

Run the test suite:

```bash
npm test
```

Tests are in `src/test/extension.test.ts`. Add tests for new flag kinds, command definitions, etc.

### Manual Testing

1. Launch the Extension Development Host:

   ```bash
   npm run watch
   # In VS Code: Press F5 or Run → Start Debugging
   ```

2. Open a Salesforce project folder in the Extension Development Host window.

3. Execute your command from the Command Palette or sidebar.

4. Verify:
   - Prompts display correctly
   - Values are collected properly
   - Command runs with correct arguments
   - Output appears in the Apx channel
   - Error handling works as expected

### Checking Generated Output

After regenerating commands, verify the output:

```bash
npm run gen:commands
cat src/registry/commands.generated.ts  # Check the generated TypeScript
cat package.json | grep -A20 '"commands"'  # Check updated contributes
```

## Development Workflow

1. Make a change to source or registry configuration
2. If changing registry config: run `npm run gen:commands`
3. Run type checking: `npm run check-types`
4. Run linting: `npm run lint`
5. Run tests: `npm test`
6. Test in Extension Development Host (F5)
7. Commit with clear message

## Performance Considerations

- **Command Registry Generation** — Fast (<1s), safe to regenerate often
- **SF Detection** — Runs once per session (cached)
- **Input Gathering** — Linear in number of flags (typically 5-15)
- **Process Spawning** — Depends on CLI plugin, typically 1-10s
- **Output Streaming** — Real-time, no buffering

If you notice slowness, profile in the Extension Development Host's Debug Console.

## Troubleshooting

### New command doesn't appear

1. Check `npm run gen:commands` was run and succeeded
2. Verify command is in `allowList` in `scripts/gen-commands.ts`
3. Check `package.json` contributes was updated
4. Restart the Extension Development Host

### Flag picker doesn't show

1. Verify flag `kind` is recognized in `FlagKind` type
2. Check `gatherFlag()` has a case for the kind
3. Verify test includes the kind in `knownKinds` set

### Output doesn't appear

1. Check Output Channel is created in `activate()`
2. Verify `output.show(true)` is called before running command
3. Check stderr is not being muted

### Command hangs or times out

1. Check apx CLI is working: `sf apx --help`
2. Run the command manually to see if it hangs there
3. Check for unexpected interactive prompts from the CLI itself (no apx command currently injects `--no-prompt`)
